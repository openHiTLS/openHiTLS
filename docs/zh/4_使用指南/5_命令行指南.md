# 1 概述

openHiTLS命令源码位于apps目录下，编译结果为hitls，用户可运行hitls命令来进行多种密码学操作。该工具提供了完整的密码学功能套件，包括随机数生成、对称/非对称加密、数字签名、PKI证书管理以及SSL/TLS连接等功能。

## 1.2 命令使用方式

```bash
hitls <command> [options]
```

其中`<command>`为具体的功能命令，`[options]`为该命令的参数选项。每个命令都支持`-help`选项来查看详细的使用说明。

# 2 选项

## 2.1 Provider选项

- `-provider <name>`：指定Provider的名称，也可以是Provider的路径，命令行加载并初始化此名称标识的Provider。
- `-provider-path`：指定Provider的搜索路径，与`-provider <name>`配合使用，此路径被附加到name的前面。
- `-provider-attr`：指定Provider获取算法时要使用的属性查询子句，有更详细的描述，请参阅[provider开发指南](../5_开发指南/4_provider开发指南.md#32-属性查询和provider打分机制)。

# 3 命令

## 3.1 基础命令

### 3.1.1 help

**功能**：显示所有支持的命令或特定命令的帮助信息

**用法**：

```
hitls help [命令名称]
```

**参数**：
- 无参数：显示所有支持的命令列表
- 命令名称：显示特定命令的详细帮助信息

**示例**：

```bash
hitls help                # 显示所有支持的命令
hitls help rand           # 显示rand命令的帮助信息
```

### 3.1.2 list

**功能**：列出支持的算法和功能，包括摘要、对称、非对称、MAC、随机数、KDF算法等

**用法**：
```
hitls list [-help] [-all-algorithms] [-digest-algorithms] [-cipher-algorithms] [-asym-algorithms] [-mac-algorithms] [-rand-algorithms] [-kdf-algorithms] [-all-curves]
```

**支持的选项**：
- `-help`： 显示帮助信息
- `-all-algorithms`：列出所有支持的算法
- `-digest-algorithms`：列出所有支持的摘要算法
- `-cipher-algorithms`：列出所有支持的对称算法
- `-asym-algorithms`：列出所有支持的非对称算法
- `-mac-algorithms`：列出所有支持的MAC算法
- `-rand-algorithms`：列出所有支持的随机数算法
- `-kdf-algorithms`：列出所有支持的KDF算法
- `-all-curves`：列出所有支持的曲线

**示例**：
```bash
hitls list -all-algorithms
hitls list -cipher-algorithms
hitls list -all-curves
```

## 3.2 加解密与消息摘要

### 3.2.1 enc

**功能**：对称加密和解密操作，支持多种对称算法

**用法**：

```
hitls enc -cipher <算法> {-enc|-dec} [-in <文件>] [-out <文件>] [-pass <密码来源>] [-md <算法>] [-provider name] [-provider-path path] [-provider-attr attr]
```

**支持的选项**：

- `-help`：显示帮助信息
- `-cipher <算法>`：必需，指定加密算法
- `-enc`：必须与`-dec`二选一。执行加密操作
- `-dec`：必须与`-enc`二选一。执行解密操作
- `-in <文件>`：输入文件，默认标准输入
- `-out <文件>`：输出文件，默认标准输出
- `-pass <密码来源>`：密码来源，默认进入交互式输入。格式：
  - `stdin`：标准输入
  - `pass:<密码>`：从命令行读取密码
  - `file:<文件路径>`：从文件读取密码
  - `env:<环境变量>`：从环境变量读取密码
- `-md <算法>`：密钥派生算法，默认SHA-256算法
- `-provider`,`-provider-path`, `-provider-attr`：请参阅[Provider选项](#21-provider选项)

**示例**：

```bash
# 加密文件（使用AES-256-CBC）
hitls enc -cipher aes256_cbc -enc -in plain.txt -out encrypted.enc -pass pass:mypassword

# 解密文件
hitls enc -cipher aes256_cbc -dec -in encrypted.enc -out decrypted.txt -pass pass:mypassword

# 使用SM4国密算法加密
hitls enc -cipher sm4_cbc -enc -in data.bin -out data.enc -pass stdin

# 从环境变量读取密码
export FILE_PASSWORD=mypassword
hitls enc -cipher aes256_cbc -enc -in plain.txt -out encrypted.enc -pass env:FILE_PASSWORD

# 使用SHA3-256作为密钥派生算法
hitls enc -cipher aes128_gcm -enc -in file.txt -out file.enc -pass file:password.txt -md sha3_256
```

`enc` 命令不支持 AES-WRAP 算法。

**功能**：对称加密/解密

**用法**：
```
hitls enc -cipher <alg> -enc|-dec -in <infile> -out <outfile> -pass <pass> [options]
```

**支持的选项**：
- `-help`：显示帮助信息
- `-cipher <算法>`：指定对称算法，可通过 `hitls list -cipher-algorithms` 查看
- `-enc`：加密
- `-dec`：解密
- `-in <文件>`：输入文件
- `-out <文件>`：输出文件
- `-pass <pass:xxx|file:xxx|env:xxx>`：口令来源
- `-hex`：输出/输入为十六进制编码
- `-base64`：输出/输入为Base64编码
- `-md <算法>`：指定派生密钥的摘要算法（默认SHA256）
- `-iter <count>`：指定PBKDF2密钥派生的迭代次数，未指定时使用默认值10000，`count` 的合法范围为 1 到 4294967295
- `-provider`, `-provider-path`, `-provider-attr`：参阅[Provider选项](#21-provider选项)

**说明**：
- 不加 `-hex/-base64` 时，输出为二进制格式。
- 解密时需与加密时的输出格式一致（如加密使用 `-base64`，解密也需带 `-base64`）。

**示例**：
```bash
# 默认二进制输出
hitls enc -cipher aes128_ecb -enc -in in.txt -pass pass:12345678 -out out.bin

# 十六进制输出
hitls enc -cipher aes128_ecb -enc -in in.txt -pass pass:12345678 -out out.txt -hex

# Base64输出
hitls enc -cipher aes128_ecb -enc -in in.txt -pass pass:12345678 -out out.txt -base64
```

### 3.2.2 mac

**功能**：消息认证码计算和验证

**用法**：

```
hitls mac -name <算法> {-key <字符串密钥> | -hexkey <十六进制密钥>} [-in <文件>] [-out <文件>] [-binary] [-provider name] [-provider-path path] [-provider-attr attr]
```

**支持的选项**：

- `-help`：显示帮助信息
- `-name <算法>`：指定MAC算法
- `-key <字符串密钥>`：必须与`-hexkey`二选一。以字符串形式提供密钥
- `-hexkey <十六进制密钥>`：必须与`-key`二选一。以0x开头的十六进制数形式提供密钥
- `-in <文件>`：指定输入文件，默认标准输入
- `-out <文件>`：指定输出文件，默认标准输出
- `-binary`：以二进制格式输出结果
- `-provider`,`-provider-path`, `-provider-attr`：请参阅[Provider选项](#21-provider选项)

**示例**：

```bash
# 使用字符串密钥
hitls mac -name hmac_sha256 -key "mySecretKey" -in input.txt

# 使用十六进制密钥
hitls mac -name hmac_sha256 -hexkey 0x1234567890abcdef -in input.txt

# 输出到文件
hitls mac -name hmac_sm3 -key "mykey" -in input.txt -out output.txt

# 二进制输出
hitls mac -name hmac_sm3 -key "testkey" -in input.txt -out output.bin -binary
```

`mac` 命令不支持 GMAC 算法。

### 3.2.3 dgst

**功能**：消息摘要计算和数字签名操作

**用法**：

```
hitls dgst [-md <算法>] [-sign <私钥文件> | -verify <公钥文件> -signature <签名文件>] [-out <文件>] [-c] [-signfmt <hex|bin>] [-provider name] [-provider-path path] [-provider-attr attr] [file...]
```

- 摘要模式

  ```
  hitls dgst [-md <算法>] [-out <文件>] [-c] [file...]
  ```

- 签名模式

  ```
  hitls dgst [-md <算法>] -sign <私钥文件> [-out <文件>] [-signfmt <hex|bin>] [-userid <用户ID>] [file...]
  ```

- 验证模式

  ```
  hitls dgst [-md <算法>] -verify <公钥文件> -signature <签名文件> [-signfmt <hex|bin>] [-userid <用户ID>] [file...]
  ```

**支持的选项**：

- `-help`：显示帮助信息
- `-md <算法>`：指定摘要算法，默认SHA-256算法
- `-out <文件>`：指定输出文件，默认标准输出
- `-c`：仅摘要模式下有效。输出十六进制摘要时使用冒号分隔每个字节
- `-sign <私钥文件>`：在签名模式下必需。指定私钥文件
- `-verify <公钥文件>`：在验证模式下必需。指定公钥文件
- `-signature <签名文件>`：在验证模式下必需。指定签名文件
- `-signfmt <hex|bin>`：签名输入输出格式，默认为`hex`。签名模式下指定签名输出格式，验证模式下指定
  `-signature`签名文件的输入格式
- `-userid <用户ID>`：SM2算法的用户ID，默认`1234567812345678`
- `-provider`,`-provider-path`, `-provider-attr`：请参阅[Provider选项](#21-provider选项)
- `[file...]`：要计算摘要的文件列表，默认标准输入

**示例**：

```bash
# 摘要模式
hitls dgst file1.txt file2.txt

# 摘要模式：以冒号分隔十六进制输出
hitls dgst -c file1.txt

# 签名模式：ECDSA 签名
hitls dgst -md sha256 -sign ec_private.pem -out sig.txt msg.txt

# 签名模式：输出二进制签名
hitls dgst -md sha256 -sign ec_private.pem -out sig.bin -signfmt bin msg.txt

# 签名模式：SM2签名
hitls dgst -md sm3 -userid "my_user_id" -sign sm2_private.pem -out sig.txt msg.txt

# 验证模式
hitls dgst -md sha256 -verify public.pem -signature sig.txt msg.txt

# 验证模式：读取二进制签名
hitls dgst -md sha256 -verify public.pem -signature sig.bin -signfmt bin msg.txt

# SM2验证
hitls dgst -md sm3 -userid "my_user_id" -verify sm2_pub.pem -signature sig.txt msg.txt
```

### 3.2.4 kdf

**功能**：密钥派生函数，从输入材料派生密钥

**用法**：

```
hitls kdf -keylen <字节数> {-pass <字符串密码> | -hexpass <十六进制密码>} {-salt <字符串盐值> | -hexsalt <十六进制盐值>} [-mac <算法>] [-iter <迭代次数>] [-out <文件>] [-binary] [-provider <名称>] [-provider-path <路径>] [-provider-attr <属性>] <算法...>
```

**支持的选项**：

- `-help`：显示帮助信息
- `-keylen <字节数>`：必需。派生密钥的长度（字节）
- `-pass <字符串密码>`：必须与`-hexpass`二选一。以字符串形式提供密码
- `-hexpass <十六进制密码>`：必须与`-pass`二选一。以0x开头的十六进制数形式提供密码
- `-salt <字符串盐值>`：必须与`-hexsalt`二选一。以字符串形式提供盐值
- `-hexsalt <十六进制盐值>`：必须与`-salt`二选一。以0x开头的十六进制数形式提供盐值
- `-mac <算法>`：指定MAC算法，默认HMAC-SHA256
- `-iter <迭代次数>`：指定迭代次数，默认1000
- `-out <文件>`：指定输出文件，默认标准输出
- `-binary`：二进制输出，默认十六进制
- `-provider`,`-provider-path`, `-provider-attr`：请参阅[Provider选项](#21-provider选项)
- `<算法...>`：必需，在命令末尾。指定kdf算法，以第一个参数作为算法名

**示例**：

```bash
# 基本用法
hitls kdf -keylen 32 -pass "mypassword" -salt "mysalt" pbkdf2

# 指定完整参数
hitls kdf -keylen 32 -pass "password" -salt "salt" -mac hmac_sha512 -iter 10000 -out key.txt pbkdf2

# 使用十六进制输出
hitls kdf -keylen 32 -hexpass 0x70617373776f7264 -hexsalt 0x73616c74 -iter 1000 pbkdf2

# 二进制输出到文件
hitls kdf -keylen 32 -pass "password" -salt "salt" -binary -out key.bin pbkdf2
```

### 3.2.5 passwd

**功能**：生成口令哈希，目前仅支持 SHA512-crypt

**用法**：

```
hitls passwd [-help] [-salt salt] [-rounds num] [-noverify] [-stdin] [password]
```

**支持的选项和参数**：

- `-help`：显示帮助信息
- `-salt <salt>`：指定 SHA-crypt salt setting，格式为 `[rounds=<num>$]<salt>`。该选项只能指定一次。`<num>` 必须由至少一位十进制数字组成；如果 `<num>` 中含有非数字字符，则不解析轮数，而是将整个输入按普通 salt 处理，再按 salt 规则截断；例如 `rounds=N$abc` 使用默认轮数，实际盐值为 `rounds=N`。若包含合法的 `rounds=<num>$`，小于 1000 的轮数按 1000 处理，大于 999999999 的轮数按 999999999 处理。实际盐值在第一个 `$` 或第 16 个字符处结束，不限制字符集合，但不能为空。通过该选项指定轮数时不能同时使用 `-rounds`
- `-rounds <num>`：指定 SHA-crypt 轮数，取值范围为 1000 到 999999999。未指定时默认使用 5000，输出中省略 `rounds=5000$`；显式指定时输出中包含 `rounds=<num>$`。不能与 `-salt` 中的 `rounds=<num>$` 同时使用
- `-stdin`：从标准输入逐行读取口令，每行输出一个结果。未读取到任何数据时不输出结果并返回成功；读取到空行时输出 `<NULL>`
- `-noverify`：终端交互输入时不进行二次确认；使用无名参数或 `-stdin` 时不改变行为
- `password`：可选无名参数，作为待哈希口令；空字符串输出 `<NULL>`。该口令会作为命令行参数传入，程序无法可靠清理调用方保存的参数内容

**输入来源**：

- 指定 `password` 时使用命令行参数作为口令；安全敏感场景建议优先使用终端交互或 `-stdin`
- 指定 `-stdin` 时使用标准输入作为口令来源
- 未指定 `password` 且未指定 `-stdin` 时，从终端交互读取口令
- 所有输入来源中，非空口令只使用前 256 个字节生成哈希。命令行参数和终端输入发生截断时输出告警，标准输入逐行处理时静默截断

**示例**：

```bash
hitls passwd -salt 12345678 alpha
hitls passwd -rounds 10000 -salt 12345678 alpha
hitls passwd -salt 'rounds=10000$12345678' alpha
printf 'alpha\nbeta\n' | hitls passwd -salt 12345678 -stdin
```

## 3.3 密钥和参数管理

### 3.3.1 rsa

**功能**：RSA密钥处理，包括格式转换和信息显示

**用法**：

```
hitls rsa [-help] [-in <文件>] [-out <文件>] [-text] [-noout]
```

**支持的选项**：

- `-help`：显示帮助信息
- `-in <文件>`：输入的RSA私钥文件（PEM格式），默认标准输入
- `-out <文件>`：指定输出文件，默认标准输出
- `-text`：以文本格式显示 RSA 密钥详细信息
- `-noout`：不输出PEM格式的密钥

**示例**：

```bash
# 查看密钥详细信息
hitls rsa -in rsa_private.pem -text -noout

# 输出密钥到文件
hitls rsa -in rsa_private.pem -out output.pem

# 同时输出文本和 PEM 格式文件
hitls rsa -in rsa_private.pem -text -out output.pem
```

### 3.3.2 genrsa

**功能**：生成RSA私钥

**用法**：

```
hitls genrsa -cipher <算法> [-out <文件>] <密钥长度>
```

**支持的选项**：

- `-help`：显示帮助信息
- `-cipher <算法>`：必需。指定用于加密私钥的对称加密算法
- `-out <文件>`：指定输出文件，默认标准输出
- `<密钥长度>`：必需，且在末尾。RSA密钥长度（位），支持密钥长度1024，2048，3072，4096

**示例**：

```bash
# 生成 2048 位密钥
hitls genrsa -cipher aes256_cbc -out server_key.pem 2048

# 使用SM4算法加密私钥
hitls genrsa -cipher sm4_cbc -out gm_key.pem 2048
```

### 3.3.3 genpkey

**功能**：生成各种类型的公钥、私钥

**用法**：

```
hitls genpkey -algorithm <算法> [-pkeyopt <参数名>:<值>] [-out <文件>] [-pubout <公钥文件>] [-outform <格式>] [-<算法> -pass <密码来源>]
```

**支持的选项**：

- `-help`：显示帮助信息
- `-algorithm <算法>`：必需。指定密钥算法类型
- `-pkeyopt <参数名>:<值>`：算法特定参数
  - `-pkeyopt rsa_keygen_bits:<位数>`：RSA算法。指定密钥长度（位），支持密钥长度1024，2048，3072，4096，默认2048位
  - `-pkeyopt ec_paramgen_curve:<曲线名>`：EC算法，必需。指定曲线名
  - `-pkeyopt mldsa_param:<变体>`：ML-DSA算法，必需。指定算法的变体，支持变体ML-DSA-44，ML-DSA-65，ML-DSA-87
- `-out <文件>`：指定输出私钥的文件，默认标准输出
- `-pubout <文件>`：指定输出公钥的文件
- `-outform <格式>`：输出的格式，支持PEM和DER
- `-<算法>`：指定加密输出私钥的算法
- `-pass <密码来源>`：加密输出私钥的算法所用的密码来源，默认进入交互式输入。格式：
  - `stdin`：标准输入
  - `pass:<密码>`：从命令行读取密码
  - `file:<文件路径>`：从文件读取密码
  - `env:<环境变量>`：从环境变量读取密码

**示例**：

```bash
# 生成2048位RSA密钥
hitls genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out rsa_key.pem

# 生成4096位RSA密钥并用AES-256加密
hitls genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:4096 -aes256_cbc -pass pass:mypassword -out rsa_encrypted.pem

# 生成EC密钥（P-256曲线）
hitls genpkey -algorithm EC -pkeyopt ec_paramgen_curve:P_256 -out ec_key.pem

# 生成密钥并同时输出公钥和私钥
hitls genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out private.pem -pubout public.pem

# 以DER格式输出密钥
hitls genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -outform DER -out key.der
```

### 3.3.4 pkey

**功能**：公钥私钥处理工具

**用法**：

```
hitls pkey [-in <文件>] [-passin <密码来源>] [-out <文件>] [-pubout] [-<算法> -passout <密码来源>] [-text] [-noout]
```

**支持的选项**：

- `-help`：显示帮助信息
- `-in <文件>`：输入密钥文件，仅支持PEM格式，默认标准输入
- `-passin <密码来源>`：输入文件的解密密码，若输入文件是加密的且未指定此选项，则默认进入交互式输入。格式：
  - `stdin`：标准输入
  - `pass:<密码>`：从命令行读取密码
  - `file:<文件路径>`：从文件读取密码
  - `env:<环境变量>`：从环境变量读取密码
- `-out <文件>`：输出文件，默认标准输出
- `-pubout`：从私钥中提取公钥输出
- `-<算法>`：指定加密算法加密输出的私钥
- `-passout <密码来源>`：输出文件的加密密码，若指定了加密算法且未指定此选项，则默认进入交互式输入。格式：
  - `stdin`：标准输入
  - `pass:<密码>`：从命令行读取密码
  - `file:<文件路径>`：从文件读取密码
  - `env:<环境变量>`：从环境变量读取密码
- `-text`：仅支持RSA。以文本形式打印密钥详细信息
- `-noout`：不输出PEM格式的密钥

**示例**：

```bash
# 从私钥提取公钥
hitls pkey -in private.pem -pubout -out public.pem

# 以文本格式查看RSA密钥详情
hitls pkey -in rsa_private.pem -text -noout

# 使用AES-256-CBC加密私钥
hitls pkey -in private.pem -aes256_cbc -passout pass:mypassword -out private_enc.pem

# 解密已加密的私钥
hitls pkey -in private_enc.pem -passin pass:mypassword -out private_dec.pem

# 重新加密私钥
hitls pkey -in old_enc.pem -passin pass:oldpass -aes128_cbc -passout pass:newpass -out new_enc.pem
```

### 3.3.5 pkeyutl

**功能**：使用密钥进行加密、解密、签名、验证等操作

**用法**：

```
hitls pkeyutl {-encrypt | -decrypt | -derive} [-pubin <公钥文件>] [-prvin <私钥文件>] [-in <文件>] [-out <文件>] [-inkey <本方密钥>] [-peerkey <对方公钥>] [-userid <用户ID>] [-inR <对方R文件>] [-outR <输出R文件>] [-inr <本方r文件>] [-outr <输出r文件>] [-rpass <密码来源>]
```

- 加密模式

  ```
  hitls pkeyutl -encrypt -pubin <公钥文件> -in <明文文件> -out <密文文件>
  ```

- 解密模式

  ```
  hitls pkeyutl -decrypt -prvin <私钥文件> -in <密文文件> -out <明文文件>
  ```

- 密钥交换模式

  ```
  hitls pkeyutl -derive -inkey <本方私钥> -userid <用户ID> [-peerkey <对方公钥>] [-inR <对方R文件>] [-outR <输出R文件>] [-inr <本方r文件>] [-outr <输出r文件>] [-rpass <密码来源>] [-out <共享密钥文件>]
  ```

**支持的选项**：

- `-help`：显示帮助信息
- `-encrypt`：必须与`-decrypt`和`-derive`三选一。执行公钥加密操作，仅支持SM2加密
- `-decrypt`：必须与`-encrypt`和`-derive`三选一。执行私钥解密操作，仅支持SM2解密
- `-derive`：必须与`-encrypt`和`-decrypt`三选一。执行密钥交换操作，仅支持SM2密钥协商
- `-pubin <公钥文件>`：加密时必需。用于加密的公钥/私钥文件（PEM格式）
- `-prvin <私钥文件>`：解密时必需。用于解密的私钥文件（PEM 格式）
- `-in <文件>`：加密或解密时必需。输入文件
- `-out <文件>`：加密或解密时必需。输出文件
- `-inkey <本方私钥文件>`：密钥交换时必需。本方私钥文件（PEM格式）
- `-peerkey <文件>`：计算共享密钥时必需。对方公钥/私钥文件（PEM格式）
- `-userid <用户ID>`：SM2 算法的用户 ID，默认`1234567812345678`
- `-outR <输出R文件>`：密钥交换时，输出本方临时公钥（十六进制格式）
- `-outr <输出r文件>`：密钥交换时，输出本方临时私钥 r（PKCS#12加密格式）
- `-inr <文件>`：密钥交换时，输入本方之前保存的临时私钥r（PKCS#12文件）
- `-rpass <密码来源>`：使用`-outr`/`-inr`时，加密/解密临时私钥 r 所用的密码来源。若使用了`-outr`/`-inr`，未指定此选项，默认进入交互式输入
  - `stdin`：标准输入
  - `pass:<密码>`：从命令行读取密码
  - `file:<文件路径>`：从文件读取密码
  - `env:<环境变量>`：从环境变量读取密码

- `-provider`,`-provider-path`, `-provider-attr`：请参阅[Provider选项](#21-provider选项)

**示例**：

```bash
# 加密明文文件
hitls pkeyutl -encrypt -pubin pub.pem -in plaintext.txt -out ciphertext.txt

# 使用私钥解密密文
hitls pkeyutl -decrypt -prvin prv.pem -in ciphertext.txt -out decrypted.txt

# SM2密钥交换，第一步：A方（发起方）生成临时公钥 R_A 和临时私钥 r_A
hitls pkeyutl -derive -inkey prv_a.pem -userid "1234567812345678" -outR R_a.txt -outr r_a.p12 -rpass pass:test1234

# SM2密钥交换，第二步：B方（响应方）接收 R_A，生成 R_B，并计算共享密钥
hitls pkeyutl -derive -inkey prv_b.pem -userid "1234567812345678" -outR R_b.txt -outr r_b.p12 -rpass pass:test1234 -inR R_a.txt -peerkey pub_a.pem -out shared_b.txt

# SM2密钥交换，第三步：A方接收 R_B，加载之前保存的 r_A，计算共享密钥
hitls pkeyutl -derive -inkey prv_a.pem -userid "1234567812345678" -inr r_a.p12 -rpass pass:test1234 -inR R_b.txt -peerkey pub_b.pem -out shared_a.txt

# 密钥交换，只生成临时密钥，不计算共享密钥
hitls pkeyutl -derive -inkey prv_a.pem -userid "1234567812345678" -outR R_a.txt
```

## 3.4 PKI证书管理

### 3.4.1 pkcs12

**功能**：PKCS#12格式证书和密钥包的处理

**用法**：

- 导出模式（创建 PKCS#12 文件）

  ```
  hitls pkcs12 -export -in <证书文件> -inkey <私钥文件> [-out <文件>] [-passin <密码来源>] [-passout <密码来源>] [-name <友好名称>] [-caname <CA名称>]... [-chain -CAfile <CA证书文件>] [-keypbe <算法>] [-certpbe <算法>] [-macalg <算法>]
  ```

- 导入模式（解析 PKCS#12 文件）

  ```
  hitls pkcs12 -in <PKCS12文件> [-out <文件>] [-passin <密码来源>] [-passout <密码来源>] [-clcerts] [-<算法>]
  ```

**支持的选项**：

- `-help`：显示帮助信息
- `-export`：启用导出模式，此模式用于创建 PKCS#12 文件。若未指定此选项，则是导入模式，用于解析 PKCS#12 文件
- `-in <文件>`：必需。输入文件，导出时为 PEM 证书文件，导入时为 PKCS#12 文件
- `-out <文件>`：输出文件，导出时为PKCS#12 文件，导入时为PEM文件，默认标准输出
- `-passin <密码来源>`：输入文件密码来源，默认交互式输入
  - `stdin`：标准输入
  - `pass:<密码>`：从命令行读取密码
  - `file:<文件路径>`：从文件读取密码
  - `env:<环境变量>`：从环境变量读取密码
- `-passout <密码来源>`：输出文件密码来源，默认交互式输入
  - `stdin`：标准输入
  - `pass:<密码>`：从命令行读取密码
  - `file:<文件路径>`：从文件读取密码
  - `env:<环境变量>`：从环境变量读取密码
- `-inkey <文件>`：导出模式下必需。指定私钥文件（PEM格式）。
- `-clcerts`：导入模式下有效。仅输出用户证书
- `-name <字符串>`：导出模式下有效。设置用户证书和私钥的友好名称
- `-caname <字符串>`：导出模式下有效。设置CA证书的友好名称。当输入文件中包含多个 CA 证书时，可以多次指定 `-caname`为每个 CA 证书分别设置友好名称
- `-chain`：导出模式下有效，包含证书链。
- `-CAfile <文件>`：导出模式下有效，使用`-chain`时必需。CA证书文件（PEM格式）
- `-keypbe <算法>`：导出模式下有效。私钥的PBE加密算法，默认`PBES2`（PKCS#5 v2.0 加密方案）
- `-certpbe <算法>`：导出模式下有效。证书的PBE加密算法，默认`PBES2`（PKCS#5 v2.0 加密方案）
- `-macalg <算法>`：导出模式下有效。MAC 完整性校验的摘要算法，默认`sha256`（SHA-256 摘要算法）
- `-<算法>`：导入模式下有效。输出私钥的加密算法，默认`aes256_cbc`（AES-256-CBC加密算法）

**示例**：

```bash
# 从证书和私钥创建 PKCS#12 文件
hitls pkcs12 -export -in user_cert.pem -inkey user_prv.pem -out user.p12 -passin pass: -passout pass:test1234 -name "My User Key"

# 创建包含 CA 证书的 PKCS#12 文件
hitls pkcs12 -export -in bundle.pem -inkey user_prv.pem -out user.p12 -passin pass: -passout pass:test1234 -name "MyUser" -caname "MyCA"

# 创建包含证书链的 PKCS#12 文件
hitls pkcs12 -export -in user_cert.pem -inkey user_prv.pem -out user.p12 -passin pass: -passout pass:test1234 -chain -CAfile ca_chain.pem -name "ChainUser"

# 使用自定义 MAC 算法创建 PKCS#12 文件
hitls pkcs12 -export -in user_cert.pem -inkey user_prv.pem -out user.p12 -passin pass: -passout pass:test1234 -macalg sha512

# 解析 PKCS#12 文件并输出证书和私钥
hitls pkcs12 -in user.p12 -out output.pem -passin pass:test1234 -passout pass:newpass
```

### 3.4.2 x509

**功能**：X.509证书的生成、解析、转换和验证

**用法**：

```
hitls x509 [-help] [-in <文件>] [-inform PEM|DER] [-out <文件>] [-outform PEM|DER] [-noout] [-req] [-signkey <私钥文件>] [-CA <CA证书> -CAkey <CA私钥>] [-days <天数>] [-set_serial <序列号>] [-md <算法>] [-extfile <扩展配置文件>] [-extensions <配置段名>] [-passin <密码来源>] [-userid <SM2用户ID>] [-text] [-issuer] [-subject] [-hash] [-fingerprint] [-pubkey] [-nameopt oneline|multiline|rfc2253]
```

**支持的选项**：

- `-help`：显示帮助信息
- `-in <文件>`：输入文件，输入证书或CSR，默认标准输入
- `-inform PEM|DER`：输入文件格式，从`PEM`和`DER`中选择一个，默认PEM格式
- `-out <文件>`：输出文件，默认标准输出
- `-outform PEM|DER`：输出文件格式，从`PEM`和`DER`中选择一个，默认PEM格式
- `-noout`：不输出证书编码数据
- `-req`：指示输入为CSR，对其签名并输出证书
- `-signkey <文件>`：须指定`-req`选项才能使用。自签名私钥文件（PEM 格式），不能与 `-CA` 同时使用
- `-CA <文件>`：须指定`-req`选项才能使用。CA证书文件（PEM格式），必须与`-CAkey`配合使用。
- `-CAkey <文件>`：须指定`-req`选项才能使用。CA 私钥文件（PEM 格式），必须与 `-CA` 配合使用
- `-days <天数>`：须指定`-req`选项才能使用。证书有效期（天），必须为整数，默认30
- `-set_serial <十六进制值>`：须指定`-req`选项才能使用。证书序列号，以`0x`开头的十六进制值，默认随机生成的20字节数
- `-md <算法>`：签名/指纹摘要算法，签名默认`sha256`，指纹默认`sha1`
- `-extfile <文件>`：须指定`-req`选项才能使用。X.509v3 扩展配置文件，需与 `-extensions` 配合使用
- `-extensions <段名>`：须指定`-req`选项才能使用。配置文件中的段名，需与 `-extfile` 配合使用
- `-passin <密码来源>`：须指定`-req`选项才能使用。私钥/证书文件的密码来源，默认交互式输入
  - `stdin`：标准输入
  - `pass:<密码>`：从命令行读取密码
  - `file:<文件路径>`：从文件读取密码
  - `env:<环境变量>`：从环境变量读取密码
- `-userid <ID>`：须指定`-req`选项才能使用。SM2 签名时使用的用户 ID
- `-text`：以文本形式打印证书完整信息
- `-issuer`：打印签发者DN
- `-subject`：打印主体DN
- `-hash`：打印主体DN的哈希值
- `-fingerprint`：打印证书指纹
- `-pubkey`：输出证书中的公钥（PEM 格式）
- `-nameopt <格式>`：DN显示格式，默认`oneline`
  - `oneline`：单行显示
  - `multiline`：多行缩进显示，每个属性独占一行
  - `rfc2253`：RFC 2253 格式，逆序显示

**补充说明**：扩展文件采用 INI 风格的配置格式，支持的扩展类型包括：

| 扩展名                   | 说明               | 示例值                         |
| ------------------------ | ------------------ | ------------------------------ |
| `basicConstraints`       | 基本约束           | `CA:TRUE` 或 `CA:FALSE`        |
| `keyUsage`               | 密钥用途           | `critical,keyCertSign,cRLSign` |
| `extendedKeyUsage`       | 扩展密钥用途       | `serverAuth,clientAuth`        |
| `subjectAltName`         | 主体备选名称       | `DNS:example.com,IP:1.2.3.4`   |
| `subjectKeyIdentifier`   | 主体密钥标识符     | `hash`                         |
| `authorityKeyIdentifier` | 颁发机构密钥标识符 | `keyid` 或 `keyid:always`      |

示例配置文件`ext.cnf`如下：

```ini
[v3_ca]
basicConstraints = CA:TRUE
keyUsage = critical,keyCertSign,cRLSign
subjectKeyIdentifier = hash
authorityKeyIdentifier = keyid:always
```

**示例**：

```bash
# 查看 PEM 证书的详细信息
hitls x509 -in cert.pem -text -noout

# 打印证书的签发者和主体信息
hitls x509 -in cert.pem -issuer -subject -noout

# 基于 CSR 生成自签名证书，设置有效期365天
hitls x509 -req -in request.csr -signkey private_key.pem -days 365 -out cert.pem

# 使用 CA 签发证书
hitls x509 -req -in request.csr -CA ca_cert.pem -CAkey ca_key.pem -days 365 -out signed_cert.pem

# 指定序列号和摘要算法签发证书
hitls x509 -req -in request.csr -signkey key.pem -set_serial 0x01 -md sha384 -days 365 -out cert.pem

# 将 PEM 格式证书转换为 DER 格式
hitls x509 -in cert.pem -outform DER -out cert.der

# 以多行格式显示DN名称
hitls x509 -in cert.pem -subject -nameopt multiline -noout

# 提取证书中的公钥
hitls x509 -in cert.pem -pubkey -noout

# 打印证书指纹（使用 SHA-256）
hitls x509 -in cert.pem -fingerprint -md sha256 -noout

# 签发带 v3 扩展的 CA 证书
hitls x509 -req -in ca.csr -signkey ca_key.pem -days 3650 -extfile ext.cnf -extensions v3_ca -out ca_cert.pem

# 使用加密私钥签发证书
hitls x509 -req -in request.csr -signkey encrypted_key.pem -passin pass:MyPassword123 -out cert.pem
```

### 3.4.4 verify

- `-CAfile <文件>`：必需。信任 CA 证书文件（PEM 格式），可以是包含多个 CA 证书的 bundle 文件

hitls verify -CAfile root_ca_cert.pem -nokeyusage sign_only_cert.pem

### 3.4.5 req

**功能**：证书签名请求的生成和处理

**用法**：

- 生成新的 CSR

  ```
  hitls req -new -subj <DN> [-key <私钥文件>] [-keyform PEM|DER] [-mdalg <算法>] [-config <配置文件>] [-passin <密码来源>] [-passout <密码来源>] [-out <文件>] [-outform PEM|DER] [-verify] [-text] [-noout]
  ```

- 查看/验证已有CSR

  ```
  hitls req [-in <文件>] [-inform PEM|DER] [-verify] [-text] [-noout] [-out <文件>] [-outform PEM|DER]
  ```

**支持的选项**：

- `-help`：显示帮助信息
- `-new`：生成新CSR模式，查看/验证已有CSR模式互斥
- `-verify`：验证CSR的自签名。如果和`-new`同时使用，则验证新生成的CSR
- `-mdalg <算法>`：仅生成新CSR时有效。签名摘要算法，默认SHA256（RSA）/SM3（SM2）/SHA512（ED25519）
- `-subj <DN>`：生成新CSR时必需。证书主体DN，格式为`/type1=value1/type2=value2/...`
- `-key <文件>`：私钥文件，生成新CSR用于签名。默认自动生成2048位RSA私钥
- `-keyform PEM|DER`：私钥文件的格式，从`PEM`和`DER`中选择一个。如果未指定此选项，则默认自动检测格式
- `-passin <密码来源>`：读取加密私钥的密码来源，默认交互式输入
  - `stdin`：标准输入
  - `pass:<密码>`：从命令行读取密码
  - `file:<文件路径>`：从文件读取密码
  - `env:<环境变量>`：从环境变量读取密码
- `-passout <密码来源>`：自动生成密钥时加密输出密钥文件的密码来源，默认交互式输入
  - `stdin`：标准输入
  - `pass:<密码>`：从命令行读取密码
  - `file:<文件路径>`：从文件读取密码
  - `env:<环境变量>`：从环境变量读取密码
- `-noout`：不输出CSR编码数据
- `-text`：以文本形式打印CSR完整信息
- `-config <文件>`：仅生成新CSR时有效。配置文件，用于添加扩展
- `-in <文件>`：输入CSR文件，默认标准输入
- `-inform PEM|DER`：输入CSR文件格式，从`PEM`和`DER`中选择一个，默认PEM格式
- `-out <文件>`：输出文件，默认标准输出
- `-outform PEM|DER`：输出CSR文件格式，从`PEM`和`DER`中选择一个，默认PEM格式

**补充说明**：配置文件采用 INI 风格，**必须**包含 `[req]` 段，通过 `req_extensions` 指向扩展段，支持类型如下

| 类型前缀  | 说明                | 示例值                   |
| --------- | ------------------- | ------------------------ |
| `DNS`     | DNS域名             | `DNS:example.com`        |
| `IP`      | IP地址（IPv4/IPv6） | `IP:192.168.1.1`         |
| `email`   | 电子邮件地址        | `email:user@example.com` |
| `URI`     | 统一资源标识符      | `URI:http://example.com` |
| `dirName` | 目录名              | `dirName:dir_section`    |

示例配置文件如下

```ini
[req]
req_extensions = req_ext

[req_ext]
subjectAltName = DNS:example.com, DNS:www.example.com, IP:192.168.1.1, email:user@example.com
```

**示例**：

```bash
# 生成基本 RSA CSR
hitls req -new -key rsa_key.pem -subj "/CN=User/O=MyOrg/C=CN" -out request.csr

# 指定 SHA-384 摘要算法
hitls req -new -key rsa_key.pem -subj "/CN=User/C=CN" -mdalg sha384 -out request.csr

# 使用加密私钥生成 CSR
hitls req -new -key encrypted_key.pem -passin pass:MyPassword123 -subj "/CN=User/O=Org/C=CN" -out request.csr

# 生成带 SAN 扩展的 CSR
hitls req -new -key rsa_key.pem -subj "/CN=example.com/O=MyOrg/C=CN" -config san.cnf -out san_request.csr

# 查看 CSR 文本信息，同时显示文本和输出 PEM
hitls req -in request.csr -text -out request_copy.csr

# 验证 CSR 自签名
hitls req -in request.csr -verify -noout

# 生成 CSR 并立即验证
hitls req -new -key rsa_key.pem -subj "/CN=User/C=CN" -verify -out request.csr
```

## 3.5 SSL/TLS通信

### 3.5.1 s_client

**功能**：建立 TLS、TLCP 或 DTLCP 客户端连接，支持指定协议版本、密码套件、信任链和客户端证书。

**用法**：

```bash
hitls s_client -host <主机> [-port <端口>] [-tls|-tls1_2|-tls1_3|-tlcp|-dtlcp]
    [-cipher <密码套件>] [-CAfile <文件>] [-chainCAfile <文件>]
    [-cert <文件> -key <文件>] [-noverify] [-state] [-prexit]
```

**主要选项**：

- `-tls`：使用 TLS，默认允许协商 TLS 1.2 或 TLS 1.3。
- `-tls1_2`、`-tls1_3`：只允许指定的 TLS 版本。
- `-cert <文件>`、`-key <文件>`：配置 TLS 客户端证书和私钥，用于双向认证；必须成对使用。
- `-cipher <密码套件>`：指定以冒号分隔的密码套件列表；同时接受标准 `TLS_*` 名称和 openHiTLS `HITLS_*` 名称。
- `-CAfile <文件>`、`-chainCAfile <文件>`：配置服务端证书验证使用的 CA 与中间证书。
- `-noverify`：不验证服务端证书；该选项不影响客户端发送自身证书。
- `-tlcp_sign_cert/-tlcp_sign_key`、`-tlcp_enc_cert/-tlcp_enc_key`：配置 TLCP/DTLCP 签名与加密证书对。

**TLS 1.3 双向认证示例**：

```bash
hitls s_client -host 127.0.0.1 -port 4433 -tls1_3 \
    -CAfile ca.pem -chainCAfile intermediate.pem \
    -cert client.pem -key client.key.pem
```

### 3.5.2 s_server

**功能**：启动 TLS、TLCP 或 DTLCP 服务端，支持指定协议版本、密码套件、服务端证书以及客户端证书验证策略。

**用法**：

```bash
hitls s_server [-accept <主机:端口>] [-port <端口>] [-tls|-tls1_2|-tls1_3|-tlcp|-dtlcp]
    [-cipher <密码套件>] [-CAfile <文件>] [-chainCAfile <文件>]
    [-cert <文件> -key <文件>] [-noverify] [-accept_once] [-state]
```

`-cert/-key` 配置 TLS 服务端证书和私钥。服务端默认验证客户端证书；使用 `-CAfile/-chainCAfile` 指定信任链，或使用 `-noverify` 关闭客户端证书验证。协议、密码套件和 TLCP 证书选项的规则与 `s_client` 相同。

**TLS 1.3 双向认证示例**：

```bash
hitls s_server -accept 127.0.0.1:4433 -tls1_3 \
    -cert server.pem -key server.key.pem \
    -CAfile ca.pem -chainCAfile intermediate.pem
```

## 3.6 其他实用工具

### 3.6.1 rand

**功能**：生成随机数据
**用法**：

```
hitls rand [-help] [-out file] [-algorithm alg] [-hex] [-base64] [-provider name] [-provider-path path] [-provider-attr attr] numbytes
```

**支持的选项**：
- `-help`：显示帮助信息
- `-hex`：以十六进制格式输出，默认以二进制格式输出
- `-base64`：以Base64格式输出，默认以二进制格式输出
- `-out <文件>`：将输出写入指定文件，若未指定，输出至stdout
- `-algorithm <算法>`：指定随机数生成算法，支持的随机数算法可使用[list](#312-list)命令查看
- `-provider`,`-provider-path`, `-provider-attr`：请参阅[Provider选项](#21-provider选项)

**示例**：
```bash
# 生成16字节随机数据，以二进制格式输出
hitls rand 16

# 生成32字节随机数据，以十六进制格式输出
hitls rand -hex 32

# 生成64字节随机数据，以Base64格式保存到rand.txt
hitls rand -base64 -out rand.txt 64

# 使用hmac-sha256随机数算法生成10字节随机数据，以十六进制格式输出
hitls rand -algorithm hmac-sha256 -hex 10
```

### 3.6.2 prime

**功能**：生成和检测素数

**用法**：

```
hitls prime [-help] [-generate] [-bits num] [-hex] [-checks num] [number]
```

**支持的选项**：

- `-help`：显示帮助信息
- `-bits <n>`：指定生成素数的位数
- `-hex`：使用十六进制格式输入/输出，默认十进制格式
- `-generate`：生成素数模式
- `-checks <n>`：素数检测的迭代轮数，默认64轮

**示例**：

```bash
# 检测十进制数字是否为素数
./hitls prime 17

# 检测十六进制数字
./hitls prime -hex 1F

# 自定义检测次数
./hitls prime -checks 128 97

# 生成 256 位素数
./hitls prime -generate -bits 256

# 以十六进制格式输出
./hitls prime -generate -bits 128 -hex
```

### 3.6.3 errdecode

**功能**：将错误码转换为可读的字符串

**用法**：

```
hitls errdecode [-help] [-v | --verbose] [--stack] [-hex] [error_code ...]
```

**支持的选项**：

- `-help`：显示帮助信息
- `-v`, `--verbose`：显示详细的错误码字段分解
- `--stack`：显示错误栈（如果支持）
- `-hex`：强制使用十六进制解析

**参数**：

- `error_code`：错误码，支持十进制或十六进制格式
  - 十六进制可以带（0x）或不带前缀
  - 可以指定多个错误码

**示例**：

```bash
# 解析十进制错误码
hitls errdecode 101

# 解析十六进制错误码（带0x前缀）
hitls errdecode 0x0E000065

# 解析十六进制错误码（不带0x前缀）
hitls errdecode 0E000065

# 显示详细的错误码字段分解
hitls errdecode -v 0x1408F10B

# 批量处理多个错误码
hitls errdecode 101 0x0E000065 234567890

# 从管道读取错误码
echo "0x1408F10B" | hitls errdecode

# 显示错误栈
hitls errdecode --stack
```
